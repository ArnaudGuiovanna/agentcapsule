# Encrypted container creation

`internal/volumestore` prepares a regular LUKS2 file. Its result is a
**container**, not a ready filesystem or an activated agent. The reserved size
is that of the logical file; the LUKS header and the future filesystem's
metadata take part of this capacity.

The worker obtains a random 32-byte key from the durable authority
(`keyauthority`) before `Prepare` (`internal/worker/provisioning_linux.go`). A
retry must supply the same key. This layer keeps only its fingerprint, with the
agent, the volume identity and its size. It implements neither the key
authority, nor key erasure, nor restore.

Creation uses libcryptsetup in the Go process, with AES-XTS and a volume key
generated by the library. The 32-byte input opens the Argon2id keyslot; it is
not a human password. No secret is written to the log, the environment or the
command line.

The process holds a journal lock and a `flock` on the inode for the whole
operation. libcryptsetup's internal metadata locks are disabled in this
process, because they would reopen and lock the same file under another
descriptor. They are replaced by the lock held during the whole creation.
**All calls to this library in this process must respect this contract**; no
other unprotected call may be added.

The reserved journal is synced before allocation. A `.pending` file can be
resumed or reformatted as long as it was never published. After formatting,
key/UUID verification and sync, a link publishes the same inode without
overwriting a destination; the intermediate name is then removed and the
journal moves to `READY`. An interruption between these steps resumes the same
inode.

A published file that is missing, replaced, altered or associated with another
reservation is refused. It is never recreated or reformatted. The `flock` is the
one used by the Firecracker driver, which excludes preparation while it is in
use. This layer opens no dm-crypt mapping and mounts no image on the host.

## Build and tests

The library requires Linux, CGO, the `libcryptsetup-dev` headers and the shared
library `libcryptsetup.so.12`. If the headers are not installed system-wide,
point `CPATH` at a directory that contains them.

```sh
CPATH=<tools-dir>/guest-build/usr/include \
  go test -race -count=1 ./internal/volumestore

python3 scripts/verify-postgres.py \
  --pg-bin <postgres-bin-dir> \
  --library-path <postgres-lib-dir> \
  --native-tools <tools-dir>/guest-build \
  --output <output-dir>/encrypted-containers
```

The tests create real LUKS2 headers, check concurrency, replay and refusals,
and interrupt a process at the durable boundaries, notably after writing the
header and before creating the keyslot. They do not establish resistance to a
power cut, the guest mount, the persistence of an encrypted filesystem or the
destruction of old keys.
